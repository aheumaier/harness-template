# ADR 0007: Frontend stack and boundaries

Status: accepted · 2026-10-27

## Context
The web app is written by agents that reach for `fetch`, hand-written types and whatever import is closest.
We want the contract to flow into the UI with types *and* runtime validation, and module boundaries a
linter can enforce.

## Decision
- pnpm 12.15.0 workspace (`apps/web`, `packages/*`) + Turborepo 2.11.10 for `typecheck`/`test`.
  pnpm 12 refuses unreviewed build scripts (`allowBuilds` in `pnpm-workspace.yaml`) and lockfile entries
  younger than its default `minimumReleaseAge`; both are kept as supply-chain sensors.
- TypeScript 6.0.3 strict (`tsconfig.base.json`), Vite 8, React 19, TanStack Query 5, Vitest 5, ESLint 10
  flat config with `typescript-eslint` `strictTypeChecked` + `react-hooks`.
- `packages/api-client` is generated by **orval 8.45.0** (`client: react-query`, `httpClient: fetch`,
  `schemas.type: zod`, `runtimeValidation`, `forceSuccessResponse`): non-2xx responses throw into TanStack's
  error channel, 2xx bodies are `zod.parse`d. `problemOf(error)` (hand-written `src/index.ts`) parses RFC 9457
  problems. `src/gen/**` is covered by `gen-check`.
- Boundaries: ESLint bans direct HTTP outside the api-client and browser globals in `packages/domain`;
  dependency-cruiser bans React/TanStack/api-client/app imports in `packages/domain` and app-to-app imports
  (also matching unresolved module names, because pnpm's strict layout leaves undeclared deps unresolved).
- knip finds unused files, exports and dependencies (check-all, drift).

## Consequences
- typescript-eslint pinned to 8.72.0 (8.72.1 was younger than pnpm's release-age cutoff at bootstrap).
- No formatter (Prettier) yet: ESLint covers correctness; add one only when formatting noise shows up in review.
